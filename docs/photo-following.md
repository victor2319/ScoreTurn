# 0.3 照片识谱与离线跟随（实验版）

原谱照片保持显示，识别结果单独存为 recognition.json，包含 MusicXML、
音符事件、小节坐标、实际演奏顺序、翻页点和人工校正。旧曲库无需迁移。
参考录音不是前提；本版尚未增加参考录音融合功能。

## 手机操作

1. 按页码顺序导入照片。PDF 仍使用旧阅读器，本版识谱入口仅支持照片。
2. 曲库右侧菜单 → **识谱与校对**。
3. 输入自建服务的 HTTPS `/recognize` 地址、服务令牌，点击联网识谱。
   只有这一步上传照片。令牌不保存，程序拒绝 HTTP 和重定向。
   也可用下面的本地命令生成 JSON，传到手机后点击“导入识谱 JSON”。
4. 检查每页小节框。橙框是翻页点（默认本页倒数第二小节）。点击小节可改
   边框百分比、该小节每个起音的 MIDI 音高、翻页点。原谱编号保留；画面中
   的连续编号从 1 开始，用于编辑实际演奏顺序。
5. 简单反复自动展开；嵌套反复、跳房子、D.C./D.S. 等复杂导航会要求填写实际演奏顺序。
   本版不能在手机上增删识别出的音符事件或小节；此类错误需在 Audiveris
   校正并重新生成识别文件，不应直接确认。
6. 点击“确认校对并保存”，返回曲库 → **离线音符跟随**。关闭网络后仍可使用。
7. 点击小节选择起点，再开始跟随。静音、匹配不足时保持页面；手动翻页会
   暂停自动翻页，点击正确小节恢复跟随。提前翻页后保留上一页剩余小节。

## 配置识谱引擎

本仓库包含服务适配器，不包含已部署的公网服务、账号或商业 API。
先从 [Audiveris 官方发布页](https://github.com/Audiveris/audiveris/releases)
安装引擎，验证其命令行能生成 `.omr` 和 `.mxl`。引擎另行遵循 AGPL 许可；
部署或分发修改版本时请查阅其 LICENSE。本适配器不内嵌或下载引擎。

```powershell
python -m pip install -r server/requirements.txt
# 替换为实际安装的命令行启动器完整路径：
$env:AUDIVERIS_BIN = 'C:\path\to\audiveris.exe'
python server/recognize_files.py page1.jpg page2.jpg --out recognition.json
```

照片必须与手机中该曲谱的照片和顺序一致。此命令先将照片按 EXIF 方向合成
多页 TIFF，再调用引擎，提取 MusicXML 和 `.omr` 内的小节坐标，不猜测坐标。
若结构和坐标数量不一致会报错。拍照倾斜、低清晰度、复杂排版会影响识别；
请先用清晰扫描件验证。Audiveris 输出结构适配需通过真实曲谱继续检验。

## 联网服务（可选）

```powershell
# 使用自己生成的随机令牌，不提交到 Git，也不要把示例文字当作令牌。
$env:SCORETURN_TOKEN = '<你的随机服务令牌>'
python server/recognize.py
```

服务只监听 `127.0.0.1:8765`。通过已有的 HTTPS 反向代理暴露 `/recognize`，
保留 Authorization 请求头，代理请求体限额至少 60 MB、超时至少 11 分钟。
手机填 `https://你的域名/recognize`。不要将裸 HTTP 端口暴露公网。
每次仅处理一个识谱任务；最多 30 张、每张 3000 万像素，总上传约 40 MB。
临时图片、引擎日志和结果在请求结束时清理。若无 HTTPS 部署条件，先用
本地 JSON 流程；App 中未配置服务时不会假装已经完成联网识谱。

## 验证范围与限制

本地 Python 测试覆盖 MusicXML 和弦／声部、简单反复、复杂导航阻断、坐标
映射及结构错误；纯 Dart 检查覆盖 PCM 分包、A4 频谱、变速、静音、噪声、
持续音、手动校正、取消上传和反复翻页。合成音频端到端测试包含泛音与不同时长的音符；这不能替代声学钢琴真机测试。完整 Flutter 编译由 CI 验证。

离线匹配器使用音级频谱和局部音符序列搜索，尚未验证音乐厅真机准确率。
它不依赖固定 BPM，但复杂踏板、相同和弦、快速装饰音、漏音和大段跳奏
可能需要手动校正；不能承诺仅上传任意照片即可可靠用于正式演出。
原始 MusicXML 保留完整信息，当前匹配器使用归一化的音符事件子集。
